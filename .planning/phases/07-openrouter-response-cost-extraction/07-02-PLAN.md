<objective>
Add `providerCostUsd` field plumbing through the post-processor worker: extract `usage.cost` from SSE `message_delta` events (per D-03, COST-02) and from non-streaming JSON response bodies (per D-05, COST-03), stash it in `RequestState.usage.providerCostUsd`, and wire `handleEnd()` to use the provider-returned cost when available instead of calling `estimateCostUSD()` (per D-04).

Purpose: Thread actual OpenRouter USD cost through both worker response paths (SSE streaming and non-streaming body JSON) so downstream consumers see real cost rather than estimates.
Output: `RequestState.usage.providerCostUsd` field populated from OpenRouter responses; `handleEnd()` conditionally skips `estimateCostUSD()` when provider cost is available.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE event stream → extractUsageFromData() | Parsed JSON from SSE `message_delta` events crosses trust boundary; `usage.cost` is provider-controlled |
| Response body JSON → extractUsageFromJson() | Decoded base64 response body JSON crosses trust boundary; `usage.cost` is provider-controlled |
| handleEnd() → DB write | `providerCostUsd` flows into `costUsd` and then into `cost_usd` column; numeric type guard prevents NaN/string/object injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-03 | Tampering | extractUsageFromData() message_delta handler (line 358) | mitigate | `typeof parsed.usage.cost === "number"` guard prevents string/non-numeric assignment to `providerCostUsd` |
| T-7-04 | Tampering | extractUsageFromJson() (line 287) | mitigate | `typeof usageObj.cost === "number"` guard prevents type confusion |
| T-7-05 | Denial of Service | handleEnd() costUsd assignment (line 665) | mitigate | `providerCostUsd` is only ever set via `typeof === "number"` guards in extraction functions; NaN is technically `typeof === "number"` but this is a pre-existing concern in the estimate path too — no new risk introduced |
| T-7-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan |
</threat_model>
