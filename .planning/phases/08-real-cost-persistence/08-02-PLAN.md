| Boundary | Description |
|----------|-------------|
| OpenRouter upstream → worker | Provider-controlled `usage.cost` (already extracted to `providerCostUsd` in Phase 7) crosses into the persistence path; this plan handles its zero-value semantics |
| Estimate fallback → DB writer | `estimateCostUSD()` returns literal `0` for unknown models — an internal value that must NOT be conflated with a real provider $0 |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-01 | Tampering | `providerCostUsd` numeric value reaching the writers | mitigate | Already guarded upstream by the `typeof === "number"` check at provider/worker extraction (Phase 7 + 08-01); this plan only changes `|| null` → `?? null` on the already-validated numeric, so no new type-confusion surface is introduced. |
| T-8-01 | Tampering (data integrity) | Estimate-$0 for unknown model persisted as real `0` | mitigate | Enforce real/estimate distinction upstream (Strategy B): map estimate `0 → undefined` in the worker `handleEnd()` estimate branch ONLY, so `?? null` collapses it to `null`. Real provider `$0` flows through the providerCostUsd branch unchanged and persists as `0`. |
</threat_model>
