<objective>
Add two behaviours to the existing `OpenRouterAnthropicProvider` class (Phase 9 artifact):
1. Unconditionally inject the `X-OpenRouter-Experimental-Metadata: enabled` request header in `transformRequestBody()` — this triggers OpenRouter to include `openrouter_metadata` in the terminal `message_stop` SSE event (D-03).
2. Tap the `message_stop` SSE event in the streaming path, extract `openrouter_metadata` (backend name, latency), and log it at `Logger` debug level — silenced unless `BETTER_CCFLARE_DEBUG` is set (D-04).

Purpose: OBS-01 — users who set `BETTER_CCFLARE_DEBUG` can see which OpenRouter backend served each request, enabling visibility into provider routing without changing the response stream.

Output: Provider class extended with header injection + debug logging tap; TDD-verified with synthetic SSE fixture. No new dependencies. No DB changes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Request headers → upstream OpenRouter | The injected header is sent to an external service |
| SSE stream → Logger debug output | Metadata content from upstream crosses into log output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04-A | Information Disclosure | log.debug(openrouter_metadata) | mitigate | Log only the `openrouter_metadata` object fields (provider name, latency). Explicitly DO NOT log the bearer token, api_key, or account credentials. Acceptance criteria enforces this. Logger output is gated behind `BETTER_CCFLARE_DEBUG` — not emitted in production by default. |
| T-10-04-B | Information Disclosure | X-OpenRouter-Experimental-Metadata header | accept | This is a public, documented OpenRouter header. Its value is the static string `"enabled"` — it contains no secrets or user-identifying data. |
| T-10-04-C | Tampering | Malicious openrouter_metadata content from upstream | accept | `openrouter_metadata` is consumed from a TLS-protected upstream response and serialized to a debug log (not passed to the client). JSON.stringify is safe against injection into the log format. No code-execution risk. |
| T-10-04-D | Denial of Service | Large openrouter_metadata payload | accept | `openrouter_metadata` is a small structured object (provider name + latency). OpenRouter's spec defines it as a fixed-shape metadata blob, not an unbounded payload. Low risk. |
</threat_model>
