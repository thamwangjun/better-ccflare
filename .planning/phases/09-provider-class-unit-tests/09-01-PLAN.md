<objective>
Create the `OpenRouterAnthropicProvider` class and prove it correct with a co-located `bun:test` suite, before any downstream wiring (type unions, CLI, HTTP API, dashboard, SSE sniffer — all Phase 10+). The class extends `AnthropicCompatibleProvider` and overrides four high-risk method groups: URL construction (`buildUrl`), request-body transformation (`transformRequestBody` with three FORK-PATCH injections + zero cache_control injection), and cost extraction (`extractUsageInfo` non-streaming, plus `parseUsage` / `extractStreamingUsage` / `readFinalSseCost` for streaming).

Purpose: Prove the four override scenarios correct in isolation so a wrong parent-class choice or buildUrl double-segment is caught by a unit test now, not by a 404 cascade once the full stack is wired.
Output: Three new files under `packages/providers/src/providers/openrouter-anthropic/` (`provider.ts`, `index.ts`, `__tests__/provider.test.ts`). No existing files modified.

Decision authority note (load-bearing): The locked decisions in 09-CONTEXT.md (D-00d, D-04) and 09-RESEARCH.md are AUTHORITATIVE over `.planning/research/PITFALLS.md` Pitfall 1. PITFALLS.md Pitfall 1 is an EARLIER draft that claimed the native SSE stream carries no `cost` field and that streaming must return `costUsd: undefined`. That premise was EMPIRICALLY REFUTED (probe 2026-06-02, captured `cost: 0.0000070581`). Per D-00d, streaming MUST surface real `usage.cost` via a ported `readFinalSseCost` — do NOT return a blanket `costUsd: undefined` for streaming. The current `openrouter/provider.ts` already implements this real-cost streaming path; mirror it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream OpenRouter response → provider cost parsing | `usage.cost` is attacker-influenceable-in-principle data from an external API; parsed into a numeric cost that persists to the DB |
| account config (`openrouter_provider_preference`) → request body | Operator-supplied JSON string parsed and injected into the outbound `body.provider` routing field |
| `account.id` → `session_id` derivation | account.id hashed to a value sent to OpenRouter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-9-01 | Tampering | `usage.cost` type confusion (string/null injected) in `extractUsageInfo` / `extractStreamingUsage` | mitigate | `typeof json.usage.cost === "number"` guard before attaching costUsd; unit tests assert null/string/absent → `undefined` (no estimate fallback for streaming). Severity: LOW (cost is informational, not auth). |
| T-9-02 | Tampering | Corrupt/malicious JSON in `openrouter_provider_preference` could throw or inject attacker-controlled provider routing | mitigate | Parse inside try/catch; on failure `log.warn` and skip injection (no throw, no partial body). `Array.isArray(pref.order) && pref.order.length > 0` guard before assigning. Inject only when `!("provider" in body)` so a client-supplied value is never overridden. Unit test feeds corrupt JSON → no throw, no provider field. Severity: LOW. |
| T-9-03 | Information Disclosure | `session_id` derived from `account.id` could leak account.id if reversible | mitigate | SHA-256 one-way digest of account.id (first 32 hex chars), not the raw id. account.id is an internal UUID, not a secret; hashing avoids echoing it verbatim. Severity: LOW (no secret material). |

**Severity summary:** No HIGH threats. Surface is a provider class with mocked-fetch unit tests, no live I/O, no auth boundary, no new DB columns. All three threats are LOW and mitigated by typeof/`in`-operator guards and a one-way hash already standard in the codebase (`pkce.ts`).
</threat_model>
