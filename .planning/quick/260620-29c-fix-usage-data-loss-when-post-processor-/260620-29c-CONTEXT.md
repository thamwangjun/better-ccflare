# Quick Task 260620-29c: Fix: usage data loss when post-processor worker enters stopped state - Context

**Gathered:** 2026-06-20
**Status:** Ready for planning

<domain>
## Task Boundary

Fix permanent usage data loss when the post-processor worker exhausts MAX_RESTARTS=3 and enters the permanently stopped state. Route new requests to the in-process UsageCollector fallback. Add exponential backoff restart recovery so the worker never permanently stops.

</domain>

<decisions>
## Implementation Decisions

### Backoff Timer Cleanup in terminate()
- Store the backoff setTimeout ID in a private field (e.g. `private restartTimer: ReturnType<typeof setTimeout> | null = null`)
- Call `clearTimeout(this.restartTimer)` inside `terminate()` before transitioning to `shutting_down`
- Prevents unnecessary callback execution and resource leaks when terminate() is called during a backoff window

### In-flight Request Mid-transition Warning
- When `safeHandleChunk` receives a requestId NOT in `collectorRequestIds` but the worker is in a stopped/shutting_down state, log a `warn` message surfacing the data loss
- Makes mid-request worker failure visible in logs — easier to diagnose than silent drops
- Pattern: check `getUsageWorker().isStopped()` inside the else branch of safeHandleChunk before calling postMessage

### Test Isolation for Module-level Set
- Export a `resetForTesting()` function from `response-handler.ts` that clears `collectorRequestIds`
- Tests call `resetForTesting()` in `beforeEach` to prevent Set state leaking between test cases
- Naming convention: the function is only for test use and should be documented as such

### Claude's Discretion
- Exact field name for the timer ID (`restartTimer`, `backoffTimer`, etc.)
- Exact log message wording for mid-transition warn
- Whether `resetForTesting()` is also used to reset any other module-level state

</decisions>

<specifics>
## Specific Ideas

- `exhaustionCycles` field on UsageWorkerController: increments each time MAX_RESTARTS is exhausted, resets `restartCount = 0` on each exhaustion
- Backoff formula: `Math.min(30_000, 1_000 * 2 ** this.exhaustionCycles)` — 1s → 2s → 4s → … capped at 30s
- `isStopped()` is a new public method on UsageWorkerController returning `this.state === "stopped"`
- `tryGetUsageCollector()` already exists in `packages/proxy/src/usage-collector.ts` — no new export needed

</specifics>
