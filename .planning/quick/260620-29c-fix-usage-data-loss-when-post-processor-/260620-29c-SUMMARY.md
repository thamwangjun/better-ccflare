# Quick Task 260620-29c: Fix usage data loss when post-processor worker enters stopped state

## What Was Done

Fixed permanent usage data loss that occurred when the post-processor worker exhausted MAX_RESTARTS=3 and entered a permanently-stopped state. All subsequent request usage data was silently dropped with no recovery path.

### Task 1 — UsageWorkerController (packages/proxy/src/usage-worker-controller.ts)

- Exported `computeBackoffDelay(exhaustionCycles: number): number` — pure function: `min(30_000, 1_000 * 2^n)`, boundaries 1s→2s→4s…→30s (capped)
- Added `private exhaustionCycles = 0` and `private restartTimer` fields
- Added `isStopped(): boolean` public method
- `attemptRestart()` now resets `restartCount=0`, increments `exhaustionCycles`, schedules `setTimeout` with computed backoff delay — no more permanent stop
- `terminate()` clears `restartTimer` unconditionally before checking state — prevents ghost restarts after shutdown
- New test file: `usage-worker-controller-restart.test.ts` (4 new tests)

### Task 2 — response-handler.ts (packages/proxy/src/response-handler.ts)

- Added `const collectorRequestIds = new Set<string>()` module-level tracking Set
- Exported `resetForTesting()` for test isolation (clears Set between tests)
- Imported `tryGetUsageCollector` from `./usage-collector`
- `safeHandleStart`: when `w.isStopped()`, adds requestId to Set and routes to in-process UsageCollector
- `safeHandleChunk`: when requestId in Set, routes to collector; else checks `w.isStopped()` for visible data-loss warn log
- `fireAndForgetEnd`: when requestId in Set, removes and routes `handleEnd()` to collector with error catch
- Extended `response-handler-worker-protocol.test.ts` with 4 new tests (stopped-path routing, Set cleanup)
- Updated `createMockWorkerSeam()` in all test files with `isStopped: mock(() => false)` to keep existing tests green
