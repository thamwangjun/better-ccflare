<objective>
Fix permanent usage data loss when the post-processor worker exhausts MAX_RESTARTS and reaches the permanently-stopped state.

Purpose: Commit 5cd0e604 introduced a silent data loss bug — after 3 consecutive worker failures, ALL subsequent request usage data is dropped with no recovery. This fix adds (1) exponential backoff restart so the worker never permanently stops, and (2) in-process UsageCollector fallback routing so requests arriving during a stopped window are still accounted for.

Output:
- Modified `usage-worker-controller.ts` with backoff restart, `exhaustionCycles` counter, `restartTimer` field, `isStopped()` public method
- Modified `response-handler.ts` with `collectorRequestIds` Set, fallback routing to `tryGetUsageCollector()`, `resetForTesting()` export
- New `usage-worker-controller-restart.test.ts` (backoff mechanics)
- Extended `response-handler-worker-protocol.test.ts` (stopped-path routing, Set cleanup)
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker process → main thread | Worker failure should not affect request data accounting |
| In-process collector fallback | UsageCollector called synchronously on hot path — errors must not propagate to client stream |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29c-01 | Denial of Service | restartTimer backoff loop | mitigate | `Math.min(30_000, ...)` caps delay; `exhaustionCycles` never resets so repeated failure stabilizes at 30s intervals rather than tight loop |
| T-29c-02 | Denial of Service | collectorRequestIds Set growth | mitigate | `fireAndForgetEnd` always deletes the ID; Set entries are bounded by concurrent in-flight requests (already bounded by server concurrency) |
| T-29c-03 | Information Disclosure | warn log for mid-request data loss | accept | Only logs requestId (internal UUID, no PII); diagnosability benefit outweighs the low-value disclosure |
| T-29c-04 | Spoofing | stale restartTimer callback firing after terminate() | mitigate | `clearTimeout(this.restartTimer)` in `terminate()` before state transition; callback checks `this.state === "stopped"` as double guard |
