# Quick Task 260613-mrg: Context

## Gray area surfaced

Upstream commit `41752084` ("remove post-processor worker dead code left behind by
PR #245") deleted `packages/proxy/src/post-processor.worker.ts` and replaced the
post-processor with `packages/proxy/src/usage-collector.ts` ("drop-in replacement").

Our branch had layered a fork feature onto that same worker across commits
`2e3cbc9d`, `1751afc2`, `aa6e85d1`, `876473f7`, `f5ab21cb`, `57880031`, `47703b18`:
extracting the **real** cost OpenRouter returns (`usage.cost` in SSE `message_delta` /
`message_start` and in non-stream JSON) and using it instead of the token-based
`estimateCostUSD`. The shared logic lives in `usage-extraction.ts`
(`extractUsageFromData`, `extractUsageFromJson`, `parseSSELine`, `resolveCostUsd`).

The conflict-resolution risk: accepting upstream's deletion as-is would have
**silently dropped** the feature, because the new `usage-collector.ts` carried its own
inline copies of the extraction functions WITHOUT the `providerCostUsd` path and called
`estimateCostUSD` directly.

## Decision

- **Worker:** port forward. Accept the deletion; make `usage-collector.ts` import the
  shared `usage-extraction.ts` functions (dedup) and call `resolveCostUsd(...)` in its
  cost step. `usage-extraction.ts` was already test-covered.
- **CLAUDE.md:** keep ours (HEAD). The block is between `<!-- gitnexus:start/end -->`
  and is regenerated by `npx gitnexus analyze`, so content choice is low-stakes.

## Notes

- `usage-collector.ts` is wired via `getUsageCollector()` in `response-handler.ts` and

- 2 SQLITE_IOERR_VNODE teardown errors in `agent-interceptor.security.test.ts` are
  pre-existing/environmental, unrelated to this change (0 test failures).
