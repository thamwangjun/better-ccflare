# Quick Task 260617-3fb: Restore async Worker-offloaded usage collector (transferable ArrayBuffers)

## Objective

Move per-request usage/cost accounting OFF the proxy's synchronous `pull()` hot path and back onto a background Bun Worker, fixing the #244 off-heap leak **properly** with transferable ArrayBuffers (copy-then-transfer, respecting client aliasing) instead of the synchronous main-thread collector PR #245 introduced. Simultaneously restore the `safePostMessage`-equivalent safety guard so a usage-accounting throw can never call `controller.error()` and discard already-enqueued client data (the "200 sent, zero bytes delivered, Claude Code hangs" regression).

**Why:** PR #245 fixed the leak by deleting the worker and running accounting synchronously on the proxy thread. That reintroduced two regressions: (1) event-loop contention (sync SSE parse competing with socket flush), and (2) data-received-but-not-delivered (the removed guard lets a collector throw tear down an in-flight client stream). The worker design is fully recoverable from `315440fa^`; the leak is solved by sending each chunk's buffer in the transfer list, and the guard is restored as a dispatch-wrapping try/catch.

Keep `fireAndForgetEnd`'s `.catch()` (commit `921062eb`) for the async rejection path.

**Config rule:** `getStorePayloads` getter cannot cross the boundary — send a `ConfigUpdateMessage` on ready and on hot-reload; worker holds a mutable `let storePayloads`. Defer via `pendingStorePayloads` if not ready.
