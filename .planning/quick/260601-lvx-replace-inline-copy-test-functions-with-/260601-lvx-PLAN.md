# Quick Task 260601-lvx

## Goal

Two test files (`packages/proxy/src/__tests__/sse-parsing.test.ts` and
`packages/proxy/src/__tests__/extract-usage-from-json.test.ts`) assert against
**inline copies** of `extractUsageFromData` / `extractUsageFromJson` rather than
the real worker functions. Drift between the copies and the shipped guards
(`typeof parsed.usage.cost === "number"` at worker line 383, `typeof usageObj.cost === "number"`
at worker line 314, and the `providerCostUsd` assignment) would go uncaught.
Point the COST-02/COST-03 tests at the real shipped functions.

## Decision: shared module (the task's fallback)

Importing `post-processor.worker.ts` directly into a test is technically possible
(probed: 190ms, passes) **but** runs the worker's top-level side effects on import —
`initPayloadEncryption()`, `new DatabaseOperations()` (opens a real DB), cleanup
intervals, tiktoken WASM init, and `self.postMessage`. That is undesirable and
potentially flaky for a focused unit test.

Therefore extract both functions into a new non-worker module
`packages/proxy/src/usage-extraction.ts`, imported by **both** the worker and the
tests. Single source of truth; no side effects in tests.

`extractUsageFromData` references the worker module-scoped `tokenEncoder` and
`log`. Inject these as **optional** params so tests can call the function exactly
as their simplified inline copies did (no token encoder ⇒ token-count branch is
skipped, matching prior test behavior).
